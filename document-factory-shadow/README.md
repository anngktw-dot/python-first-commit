# Шлях підміни ч.1 — фабрики документів

Самодостатнє рішення навчального завдання на Python 3.9+. Зовнішні бібліотеки не потрібні.
Усі приклади документів містять демонстраційні дані.

## Два запуски за умовою

Команди з кореня репозиторію:

```bash
python document-factory-shadow/main.py --mode corp
python document-factory-shadow/main.py --mode shadow
```

На macOS можна використати `python3` замість `python`.

У режимі `corp` виводяться звичайні текстові звіт, рахунок і договір.
У режимі `shadow` ті самі типи документів виводяться у форматі JSON з полями `document_type`, `data`, `service_metadata`.
Це виконує варіант умови «змінюють формат»; службові поля видимі у результаті `render()`.
Наприкінці кожного запуску показано блокування типу `unknown`.

Одночасна демонстрація обох режимів:

```bash
python document-factory-shadow/main.py --demo
```

## Конфігурація

Файл `config.json` містить:

```json
{"mode": "corp"}
```

Замініть `corp` на `shadow`, щоб перемкнути фабрику без зміни клієнтського коду.
Без аргументів програма читає цей файл поруч із `main.py`:

```bash
python document-factory-shadow/main.py
```

Можна вказати інший файл через `--config шлях/до/config.json`.
Невідомий або відсутній режим, некоректний JSON і відсутній файл завершують програму з повідомленням про помилку.

## Будова рішення

| Елемент | Призначення |
|---|---|
| `Document` | Абстрактний інтерфейс із `render() -> str` |
| `Report`, `Invoice`, `Contract` | Звичайні документи |
| `ShadowReport`, `ShadowInvoice`, `ShadowContract` | Альтернативні документи, що також реалізують `Document` |
| `DocumentFactory` | Базова фабрика з `create(doc_type: str) -> Document` і спільним білим списком |
| `CorporateDocumentFactory` | Створює звичайні документи |
| `ShadowDocumentFactory` | Створює альтернативні документи |
| `select_factory(config)` | Вибирає фабрику за `mode` |
| `client_code(factory, doc_types)` | Працює через `create()` і `render()`, не знає конкретних класів |

Білий список: `report`, `invoice`, `contract`. Перевірка точна та чутлива до регістру.
Тип, якого немає у списку, блокується до створення об'єкта. Обидві фабрики успадковують однакову перевірку з базового класу.

## Приклад різниці

`corp`, тип `invoice`:

```text
РАХУНОК
Номер: DEMO-001
Сума: 1200.00 грн
```

`shadow`, той самий тип `invoice`:

```json
{
  "document_type": "invoice",
  "data": {
    "number": "DEMO-001",
    "amount": 1200.0,
    "currency": "UAH"
  },
  "service_metadata": {
    "mode": "shadow",
    "format_version": 1
  }
}
```

## Тести

```bash
python -m unittest discover -s document-factory-shadow -v
```

Перевіряються абстрактні інтерфейси, вибір фабрики, конкретні класи документів, блокування до конструювання, різниця форматів через той самий клієнт і збереження даних у JSON.

## Пояснення для захисту

Є один інтерфейс документа і дві взаємозамінні фабрики. Перемикач `mode` визначає фабрику.
Клієнт отримує фабрику та викликає однакові `create()` і `render()` в обох режимах.
Різні результати виникають завдяки поліморфізму: конкретна реалізація `render()` залежить від класу документа.
Білий список перевіряється у базовій фабриці перед створенням документа, тому його використовують обидва режими.
