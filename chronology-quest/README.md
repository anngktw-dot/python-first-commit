# Практична робота «Хронологія»

Мета — відновити події на складі з 23:00 13 жовтня до 04:00 14 жовтня 2026 року та зіставити журнал з описом вантажів.

Потрібен Python 3.9 або новіший, сторонні бібліотеки не потрібні.

```sh
python3 main.py
```

На Windows можна використати `python main.py`. Файли шукаються поруч із програмою, тому запуск можливий із будь-якої папки.

Вхідні файли `hub_log.txt` і `inventory_recovered.txt` читаються повністю як UTF-8 і не змінюються. HTML та вебархіви відхиляються. Програма перевіряє поля, сортує за повною датою через `datetime`, вибирає період включно з його межами та обчислює інтервали різницею дат.

Результати кожного запуску перезаписуються:

- `хронологія.txt` — усі події періоду, важливі записи, інтервали й звірка з посиланнями на рядки джерел.
- `пошкоджені_рядки.txt` — неповні, порожні, пошкоджені та невідомі записи, дублікати й помилки опису зі збереженим текстом.
- `висновок.txt` — короткий висновок українською.

У наданих даних є 62 записи за потрібний період (один із невідомим типом GHOST), 0 дублікатів і 22 рядки для перевірки: 18 у журналі та 4 в описі. Невідомі типи зберігаються у хронології з попередженням, але не використовуються як докази. Дублікати залишаються видимими, проте повторно не враховуються в аналізі.

Журнал фіксує вивезення `7-Б` через ворота №3 о 00:53:10, а опис — статус «згоріло». До першого диму минуло 1 год 54 хв 45 с. Партії `7-P` немає: її номер не підмінюється схожим. Кількість і вага не вказані в журналі, тому обсяг вивезення перевірити неможливо. Час займання, причина offline та винуватці не встановлені.

Функції: `read_text` читає й перевіряє формат; `parse_log` розбирає та сортує журнал; `parse_inventory` перевіряє опис; `select_events` відбирає події; `describe` оформлює запис; `interval` рахує час; `compare_inventory` зіставляє партії; `write_reports` записує результати; `main` запускає ці кроки.
